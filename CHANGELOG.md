# Changelog

All notable changes to this project are documented here. Semantic versioning.

## [Unreleased]

### Added

- **Device capture, the one family the pack tables had no entry for.** `V25` handheld phone, `V26` fixed surveillance, `V27` webcam and video call, `F09` sensor imaging, `A09` onboard device capture. Footage that is what a device recorded had nothing in any of the four tables — `V19` photoreal live action and `V21` observational documentary are the nearest, and neither is about the recording. The gap was found by using a corpus of a thousand prompts as a coverage map rather than a source — three hundred and twenty-seven distinct style strings across ten families. Capture was its second-largest family, everything else in it already mapped onto an existing pack, and nothing was copied across. All five claim no leverage axis except `F09`'s palette remap, which is right rather than an omission — device capture is photorealism recorded badly, not a move away from it, so the wild draw should never land on one. A drone pack was considered and dropped: camera movement is already a per-shot annotation with its own vocabulary, and a motion pack for it would be a second way to say the same thing.

- **`# What the frame can show`, a new planner block.** Four consequences of base 4.1 that `# How to write` left implicit: absence cannot be drawn, so a missing thing is written as its visible evidence rather than as what is gone; count and position beat adjectives; left and right are the camera's and are fixed once; every property has to be present in a single frame. Unsourced craft, recorded in `notInTheGuides`, and reaching the planner prompt only — no value in it goes near `vocab.ts`. Spec first: the block went into `contract.json` and both directions of the block binding went red before a line of it was written.
- **The negation rule reaches the patch prompt too, and only that rule.** The asymmetry is the reason: an edit free to write "the poster is no longer there" reintroduces exactly what the planner was stopped from writing. The rest of the block is composition guidance a surgical edit has no use for, so it stays out. The call is stated in the patch block's spec note rather than left to fall out of omission.
- **Two candidate rules were dropped against the golden fixtures, and the reason is recorded.** A ban on relational placement ("beside", "behind her", "nearby") is contradicted by the guides' own worked examples — "sitting beside <Subject 3> on the sofa", "a closed black umbrella beside a silver bicycle". "Put the voice description immediately after the speaker id" is contradicted by "the middle-aged baker with a calm, slightly raspy voice (S1)", which puts it before. Both read as good craft. Neither survived one grep, which is now a rule in the working notes.

- **`reference/h3/contract.json`, the machine-readable H3 contract.** One place stating what the output must look like per mode (alignment line, section order, layout, separators, where the style clause goes), what vocabulary is legal with a guide citation per value, what blocks each system prompt carries and in what order, every diagnostic and why it is legitimate, and everything the compiler does that no guide asks for. Written independently of the code rather than generated from it, because a spec derived from the implementation agrees with it by construction and catches nothing.
- **`test/contract.test.ts` makes the spec load-bearing, in both directions.** Eighty assertions binding the spec to the implementation: the guide files still hash to what the spec recorded, every alignment template character for character, section order and layout read off the rendered golden output, every vocabulary list against the exports the code uses, both prompts' ordered blocks including which are conditional, and the diagnostic catalogue against the codes the rules actually emit. Twelve deliberate breakages confirmed it: eight in the code (a renamed section, reordered ref sections, an uncatalogued camera type, an alignment line losing its em dash, a removed prompt block, a conditional block made unconditional, an uncatalogued diagnostic, an edited guide file) and four in the spec (a wrong vocabulary value, a wrong section layout, a mode claiming the wrong contract, a diagnostic nothing emits). Adding anything to the format now means adding it to the spec first.
- **The official guides are tracked, in `reference/h3/`.** The project's central claim is that every value in `vocab.ts` traces to a line in one of them, and a claim that cannot be checked from a clean checkout is not a claim. The guide-fidelity comparison now runs everywhere rather than only where the notes happen to live, and `contract.json` beside them cites the guide section behind each value.
- **The golden fixtures are now verifiably the guides' text, and two of them were not.** `T2VA` and `Ref2VA` had been transcribed with typographic apostrophes (U+2019) where the official guides use ASCII ones — thirteen characters across the two fixture files, in both the documents and the expected output. Every byte-exact test passed, because they compared the serializer to a copy that was already wrong. `test/guide-fidelity.test.ts` closes it two ways: a byte comparison against the guide markdown where it exists, and a character-set check that runs anywhere — the worked examples are pure ASCII apart from the em dash opening the FL2VA and L2VA alignment lines, so anything else came from a transcription tool. The guides were moved into tracked space in the same run, so the comparison runs everywhere; if they ever go missing it registers as a named todo and the run summary says it did not happen.
- **`CUT_STYLE_NOT_IN_PROSE`.** A shot's cut phrasing is one of five exact strings from base guide 4.2, the document records which one, and the editor offers it as a dropdown — but nothing compared it to the prose, so changing it altered an annotation that reaches no output and then disagreed with the sentence from then on. The five golden fixtures all set it consistently already, which is what makes the rule safe: it turns none of them red.
- **One compound-speaker renderer instead of two.** `speakerRef` had no caller — the planner writes `(S1)` into the prose, as the guide asks — while the validator carried its own copy to check the prose against, and that copy sorted the ordinals lexicographically. Ten speakers would have rendered `(S10,S2)`. The validator now calls the shared one, and a test pins the ordering.
- **The Ref2VA word range comes from `vocab.ts`.** `REF_DETAIL_WORD_RANGE` was defined there, consumed by nothing, while the planner prompt named 350-500 itself — a guide number in two places, one of them dead.

- **Creative modes.** A style direction injected into the planner prompt, in four families that combine — visual medium, motion behavior, finish, audio treatment — plus a strength level that states how far the direction reaches. Three ways in: directed, a random wild draw, and off. The wild draw is restricted to combinations that score on at least three of five leverage axes with geometry or shape among them, because texture and cadence alone collapse back to H3's photorealism default.
- **Reference anchors are reachable.** All 30 are now offered in the visual picker alongside the 24 medium packs, under their own group. Previously exactly one was reachable, through a single preset.
- **`test/creative-integration.test.ts`**, covering the wiring the feature never had: that the planner prompt carries the direction and omits it when there is none, that the patch prompt derives the same text from the same record, that a creative mode survives a patch, that it changes nothing in the serialized prompt, and that a selection round-trips through the stored-document schema to the same prompt text. Seven deliberate breakages were used to confirm the checks go red for the right reason: dropping the style block from the planner, ignoring the document's style in the patch prompt, resolving unknown pack ids into text instead of skipping them, never reporting a schema failure, gating on one instead of reporting it, a patch that drops fields it does not recognise, and a pack stripped of its axes.
- **Glitch marks.** A second, independent contribution on the creative record: up to three ultra-rare tokenizer strings — the `SolidGoldMagikarp` family and its relatives — placed in the scene as visible text on surfaces that differ from each other, one appearance each. Ten tokens, six surfaces, and a register switch that decides whether the marks are the only anomaly or whether the surrounding prose also reaches for the less expected material and light while staying inside what a camera can record. Two tokens carry a documented pull of their own; they are offered and never drawn at random, and neither is the register — a draw adds marks, while changing how every sentence is worded stays a deliberate press. Three named presets and a draw button. Ported from the Sora 2 dual-stage architect's Glitch Token Infusion Edition and its standalone rewriter sibling: what came over is the placement grammar and the safety rules, not the worked examples, which are built out of timecodes and lens metrics that here are computed by code or absent from the vocabulary.
- **The marks know which pictures are actual frames.** What is forbidden everywhere — a mark in the style clause, a subject description or a retention note — is part of the derived block both prompts share. What is merely allowed is appended by the planner alone, because only it knows the mode: under I2VA, FL2VA and L2VA a mark may not be described as visible in a supplied frame, and under Ref2VA the marks stay on the environment and out of subject definitions, retention notes and the summary. A mark is on-screen text, so it goes through the contract's existing rule for that rather than a new one.
- **A mark passes the on-screen text rule that already exists.** `visibleTextQuoted` in `validate/rules/speech.ts` requires every `visibleText` entry to appear verbatim in double quotes in its beat's prose, which is exactly half the mark contract, enforced with no new rule and no prose pattern-matching. The glitch block defers to it rather than restating it, and the tests assert both directions of that rule against a marked beat — the deferral is only correct if the existing rule accepts correctly marked output.
- **Record-level derivations.** `hasDirection`, `sameRecord`, `describeRecord` and `pruneRecord` read both halves of a creative record. The selection-only versions remain, and using one where the record is meant is now the specific mistake the new hard rule names: gating generation on the style alone drops a marks-only record before it reaches the document, and comparing the style alone leaves the badge reporting no change when the marks changed.
- **`test/creative.test.ts` and `test/creative-integration.test.ts` cover the marks end to end**: the derivation is total over ids it does not have, an empty token list is the same state as no record, the ceiling holds however many are stored, the drawable pool excludes the skewed tokens, both prompts derive identical text from one record, the planner appends a different note per mode and the patch prompt appends none, and a record with marks round-trips through the stored-document schema. Eighteen deliberate breakages were used to confirm the checks go red for the right reason, among them: dropping the `glitch` key from the schema, where an object schema strips what it does not describe and the round trip is the only thing that notices; the planner never emitting the block; the patch prompt ignoring the document's marks; one mode note used for all five; the ceiling unenforced; unknown ids resolving instead of being dropped; a skewed token in the draw pool; `sameRecord` and `hasDirection` reading the style half only; and restoring a record written before marks existed as one carrying an empty set.

- **Wildcards.** `{setting}` anywhere in the idea is a category name; rolling draws a value for it. Twelve categories of content — subject, action, setting, time, weather, prop, complication, sound, material, creature, era, scale — deliberately separate from the creative packs, which decide how a clip looks rather than what is in it. `{prop:3random}` draws three distinct values, `{era:all}` takes the category. A name nothing matches stays in the text exactly as written and is reported, because an idea is the user's own sentence and quietly deleting a word out of it is worse than leaving something visible.
- **The idea box keeps the template.** Rolling derives the idea rather than overwriting it, so a second roll is still possible and the seed has something to be a seed of. Expansion happens on the way into `CompileInput` and nowhere later: a document assembled from unexpanded text would render a literal `{setting}` into the H3 prompt, and there is no downstream place to fix that. The seed goes into the version label, since the idea box still holds the template and the seed is the only record of which roll produced a document.
- **The roll travels on the document.** `{template, seed}`, both halves or neither, stamped by `assemble` and restored on load and on checkout. The version label said `seed 417301` while the template it was a seed of lived only in the idea box, which nothing persists — a partial record that read as a complete one. Checking out a seeded version now puts the idea box back in the state that produced it.
- **`assemble` stamps the input metadata, not the caller.** The creative mode and the roll were two `if`s in `compile`, past the model call, where no test could reach them: deleting either left the whole suite green. Both are derived from the input like everything else on the document, and both now have a control.
- **The experiment matrix.** Every combination of the values nominated per axis, as ideas, capped at 64 with the cap reported. A placeholder asking for several values at once — `{prop:3random}`, `{era:all}` — is not an axis: it is a decision already made, so it is drawn once from the matrix seed and held identical across every cell. Without that the same sentence meant two different things depending on which button was pressed. `:all` takes the category in its own order rather than a shuffled one, because every value in a random order is a different sentence each time for no reason. Rolling asks for something else; this holds everything fixed but one axis, which is the only way a comparison between two prompts means anything — and whether the planner's prose conditions H3 well is the open question in this repo. It stops at the text: compiling one is a model call, so that decision stays with the person pressing generate.
- **The library holds nothing the planner is forbidden to write.** Values are concrete, observable fragments, and a test checks the whole library against the abstractions the planner prompt rejects by name. A wildcard carrying "melancholy" would hand the planner a word it has been told not to use, inside the user's own idea where the style direction cannot override it. Ten deliberate breakages confirmed the checks go red, among them an unknown placeholder being deleted rather than left, draws repeating a value, the seed not reaching the draw, the matrix taking a value its category does not have, and a mood word entering the library.

- **Recognisable people are described, not named.** A widely recognised person, living, dead or fictional, reaches the prompt as the role they are known for, the era, the dress, and the traits that identify them on sight -- naming one pulls the frame toward a likeness and away from the scene that was asked for. In both the planner and the patch prompts, so an edit cannot introduce a name the prose was written to avoid, and it teaches the substitution rather than only forbidding the name. Two carve-outs: words inside a `dialogue` field and on-screen text are reproduced exactly either way, and without that the rule would contradict the instruction never to touch a user's own words. A house rule, not a contract item -- neither official guide mentions public figures -- so it lives in the prompts and not in `vocab.ts`, and there is no validator rule, because deciding whether a description names a real person is exactly the prose pattern-matching this project removed seventeen rules of.

- **Erase local data**, as a `local data` button in the header. Two scopes: the workspace, its version history and settings; or that plus every stored secret and the wrapping key. The panel lists what is stored before you press anything and, afterwards, before-and-after counts re-read from storage — it can report that something is still there, including a delete blocked by another open tab, and turns red when it does. `closeDb()` before deleting is load-bearing: an open connection blocks `deleteDatabase` indefinitely, and removing that line leaves the wipe reporting success having removed nothing.
- **`origin` key mode, now the default for storing the API key.** A random AES-GCM-256 key generated with `extractable: false` and kept as a `CryptoKey` in IndexedDB `H3KeyVault`. Its bytes never exist in JavaScript, so a copied `localStorage` blob cannot be opened on another browser or machine. It does not protect against anyone using this browser profile, or against script on this origin, and the README says so. `passphrase` mode is unchanged and remains the only mode that does not depend on the machine.
- **`test/db.test.ts`**, covering a fresh database and three broken ones: empty at version 1, missing a single store, and stores present with no indexes.
- **`test/wipe.test.ts` and `test/secureStore.test.ts`**, run against `fake-indexeddb` so deletes and round-trips are real. Every "it is gone" assertion is paired with a case where it is not. Four deliberate breakages were used to confirm the checks go red for the right reason: dropping `closeDb()`, minting a replacement wrapping key on a failed read, hardcoding the secret name instead of scanning by prefix, and making `isClean` always return true.

### Fixed

- **README claimed 37 diagnostic codes and 30 rules.** There are 36 and 29 after the cut-style deletion. Counted at runtime off `ALL_RULES` and the scan the coverage meta-test uses, not by reading.

- **`DIALOGUE_BAD_TERMINAL` fired on two shapes that are incomplete by construction.** Ref 5.4 asks for a terminal mark on "complete statements, questions, and exclamations"; the rule applied it to every line, including the first half of one crossing a cut and speech the end of the video truncates — which is the whole meaning of `<scenetrans>` and `<cutoff>`. Found by writing the fixtures above: the corpus had never contained either shape, so the rule had never been handed one to be wrong about.
- **Changing any pack silently deleted the selected glitch marks.** `DirectedControls`' `onChange` rebuilt the record as `{ mode, selection }` with no `glitch` key, so picking a Finish pack dropped the marks from the record, the badge and the chips in the same render — the exact failure CLAUDE.md's "every caller reads both" rule exists to prevent, in the one caller that did not. The four hand-written `...(glitch ? { glitch } : {})` spreads that made it possible are now one core function, `withGlitch`, so the case is held by a test instead of by clicking. Worth recording that this is the third time the same rule has been broken in this panel, in a third handler: an invariant that needs every caller to remember it will keep being forgotten until the remembering is done in one place.
- **The planner was still ordering the punctuation the validator had just stopped requiring.** The Speech block said "Never translate, paraphrase or tidy user-supplied lines" and then, in the next sentence, "End each line with . ? or !, and use no decorative punctuation" — unscoped, so it contradicted itself and base 4.4. Worse than a stray instruction: `assemble.ts` decides `userSupplied` by exact text equality against what the user submitted, so a line the planner tidied stops being recognised as supplied, loses the patch protection that keeps it verbatim, and raises no diagnostic at all. Scoping the validator without scoping the prompt that produces the text was half a fix.
- **A mode off the union survived a load.** `pruneRecord` special-cased `exploratory` and passed everything else through, so a document from a build this one does not know rendered a panel with no mode highlighted, no controls and a badge for a style the user could neither see nor edit — then wrote it back unchanged. `pruneSelection` guards `strength` against exactly this; the mode now gets the same treatment.
- **Ten duplicated tests.** Eighty byte-identical lines — `the legacy numeric anchor id`, `sameSelection` and `pruneSelection` — ran twice, and the published test count counted them twice.
- **Four dead exports in `budgets.ts`**, one of which documented the retired warning severity as if it were live. Nothing outside the file called `MIN_SHOT_MS`, `comfortableLatestCutMs`, `countWords` or `countSentences`.
- **`VISION.md` described a control as missing that the same commit added**, and the changelog counted three unmarked house values while naming two.

### Added

- **A table-wide axis check**, replacing what the preset viability sweep used to provide incidentally. It asserts the properties the tables actually have — axes drawn from the documented set, no repeats, enough leverage left for a draw — and deliberately not that every pack claims an axis, since nine correctly claim none and that is what the scores are for. Asserting otherwise was the first version and it went red against those nine.
- **Every contract vocabulary entry must carry a guide citation or a house marker.** Marking `slotCeilings` and `mediaKinds` was a data edit; without this the next entry added with neither is exactly as invisible as those two were.
- **A positive twin for the terminal-punctuation exemption**, which could otherwise have passed vacuously if the check became unreachable.

- **The Ref2VA word range was quoted without the scope the guide gives it.** ref 5.2 states 350-500 words *for generation tasks* and exempts two cases in the same sentence: video-editing descriptions scale with the complexity of the source video and are not held to the range, and dialogue-dense material fits the complete spoken timeline ahead of any count. `contract.json` encoded the bare range and the planner carried only the dialogue-dense half, so a video-editing job was told to pad toward a number the guide explicitly frees it from. The contract now records the scope beside the number, the planner states both exemptions, and `test/guide-fidelity.test.ts` fails if the range is ever stated without them — the number and its scope have to travel together. Found by an outside audit of the contract; nothing here would have caught it, since every check compared the code to the same misquotation.
- **A job can be a video edit and a generation task at once, and ref 5.2 does not say which word-count clause wins.** `taskTypes` is an array joined with ` + ` per ref 3, whose own worked example prefix is `[video editing + reference generation + audio reuse]` — so the combined case is the guide's illustration, not a corner. The contract records it as `unresolved` rather than deciding it in either direction, and the planner is told only the thing both readings rule out: never pad toward the range to satisfy it, let the information load set the length. Raised by the same outside audit, which hit the identical ambiguity classifying its own prompts.
- **A fabricated guide citation.** `src/core/normalize/budgets.ts` attributed "one dominant action beat per roughly 1-3 seconds" to "the guide". Neither guide contains "dominant", "density", or any beats-per-second rate. `MS_PER_BEAT` is house judgement and now says so, and is listed in the contract's `notInTheGuides` where the rest of the house values are.
- **The punctuation rules contradicted the base guide on dialogue the user typed.** `dialoguePunctuation` applied ref 5.4's standardization — terminal mark, no repeated or decorative punctuation — in every mode, but ref 5.4 scopes that to dialogue reused from reference audio or reperformed on request, and base 4.4 governs the other case with the opposite instruction: "Preserve every original word and punctuation mark verbatim; do not translate or rewrite them." A user who typed `Wait... what?!` got two errors demanding a rewrite the guide forbids, and `src/core/patch/apply.ts` would have refused the rewrite anyway, so the errors could not be cleared. Both codes are now scoped to `dialogue.userSupplied === false`. The field already existed; nothing read it here.
- **Two house values sat unmarked inside the contract's `vocabulary` block.** `slotCeilings` (9/3/3) and `mediaKinds` appear beside twenty guide-cited entries with the absence of a `guide` key as the only signal that neither guide states them — and neither guide states any limit on reference assets at all. Both now carry `"house": true` and a note, and `slotCeilings` is in `notInTheGuides`. `frame-grid` was listed there against the wrong file; the 17k+5 grid is in `src/core/normalize/duration.ts`.
- **A diagnostic described a check that was never written.** `VOICEOVER_PHRASE_MISSING` was catalogued as "the exact phrase and the lips-closed clause"; the rule checks only the phrase. `LIPS_CLOSED_PHRASES` in `vocab.ts` was the four-variant allowlist for the missing half, with no caller — the same shape as `REF_DETAIL_WORD_RANGE` and `speakerRef` before it. The constant is gone rather than wired up: base 4.4 mandates *stating* that the lips remain closed, not a wording, so an allowlist could only fire on legitimate prose that said it differently. The description now says the clause is a prompt instruction and why it is not a check.

- **A wildcard placeholder could reach the H3 prompt literally.** `src/core/wildcards/expand.ts` states that nothing downstream of `CompileInput` ever sees one; that was a description of how the UI happened to be wired rather than a property of anything, and three paths broke it — generating without rolling at all, checking out a version that carries no roll, and taking a matrix cell whose category the library does not have. All three end at the same call, so `compile` now refuses an idea that still carries placeholders, before a model call is spent, naming what is left.
- **A seed was recorded for a roll that drew nothing.** A template whose every name is unknown still rolls: there are placeholders and text comes back, but nothing was substituted, and the document and version label recorded a seed that reproduces the template unchanged. `rollRecord` in core decides this now, rather than an inline condition in a hook no test can reach.
- **A repeated placeholder meant two things.** `{setting} then back to {setting}` drew independently at each occurrence when rolled and used one value for both in the matrix — the same disagreement that was fixed for `{prop:3random}` and missed here. One draw per placeholder, reused at every occurrence, in both.
- **A matrix axis configured with nothing valid left its placeholder in every cell.** `experimentMatrix('a baker in {era}', { era: ['last Tuesday'] })` dropped the axis and offered `a baker in {era}` as a finished idea. It falls back to the whole category instead, and a test asserts no cell the matrix produces ever carries a placeholder.
- **Choosing a preset, or turning the creative panel off, silently discarded glitch marks.** Every other control in that panel carries them across, and the marks' own controls stay on screen when the mode reads Off — so clearing a selection the panel is still displaying was the panel disagreeing with itself. A preset that carries marks replaces them; one that carries none leaves them alone.
- **The glitch block could contradict itself about surfaces.** Nothing couples how many surfaces are chosen to how many marks there are, so one mark and six surfaces produced "place exactly these, once each" beside "use these surfaces and no others" listing six. The surfaces are phrased as a pool to draw from.
- **`CUT_STYLE_NOT_IN_PROSE` is scoped to the five ordinary phrasings.** The planner schema also accepts cross-dissolve, fade and wipe, which the prompt never teaches as prose and the editor's dropdown does not offer — a shot annotated with one raised an error nobody could clear, on a prompt that renders perfectly.
- **`speakerRef` returned `()` when no member of a compound speaker resolved**, so the validator told the user their prose had to contain an empty id, on top of the undeclared-member diagnostic that was the real problem. It returns null and the rule stands down.
- **Three exports with no callers**, added by the same session that added the rule against them: `rerollSeed` on the engine, and `getGlitchToken` and `getGlitchSurface` on the creative barrel.
- **The experiment matrix rebuilt on every render.** Up to 64 substituted strings, re-parsed and re-drawn on every keystroke and on every unrelated re-render of the panel above it. Memoized on the idea.
- **The unverified-guides todo named the wrong directory**, and the contract entry said "six in the code" while listing eight.

- **The patchable surface is pinned.** `VISION.md`'s guarantee that no transform can produce a prompt H3 cannot parse rests entirely on structure staying off `PATCHABLE_LEAVES`, and the control for it named five paths that must be rejected — a proxy, since a sixth derived field added to the allowlist passes all five. Nothing can decide mechanically whether a new leaf is derived, so the list is pinned instead, the way the contract pins the guides' sha256: growing the write surface is now a visible event that someone has to come and confirm was meant.
- **Every vocabulary claim in the contract now says where it came from, and a test enforces it.** An outside audit found `mediaKinds` and `slotCeilings` sitting unmarked among guide-cited entries, which is how a house partition and a platform limit came to read as contract. Marking them fixed the instances; this closes the class. Every leaf must cite a guide section or declare `house: true`, a citation must look like one, and a house entry must carry a note saying why it is not contract. `modes` was the one the check found on its first run: a bare array, uncited, while every entry beside it carried a citation. Four deliberate breakages confirmed it fires.

- **A category name is a lookup, never a prototype read.** `{constructor}` is not a wildcard category, so it was correctly skipped as an axis and left standing — and then the substitution found `Object.prototype.constructor` and wrote `function Object() { [native code] }` into every matrix cell. The result carries no matchable placeholder, so the compile guard saw a clean idea and a model call was spent on it. The rows are null-prototype now and every keyed read is an own-property check, at both sites.
- **`{setting}` and `{setting:random}` are one request.** The draw cache was keyed by the written form, so those two drew independently while the matrix, keyed by category, gave both the same value — the same template meaning two things depending on which button was pressed, which is the defect the neighbouring test claimed was already fixed. Keyed by category and count now, so `{prop}` and `{prop:2random}` stay separate.
- **Off is reachable again.** Keeping the marks through Off meant returning a record, and a record needs a mode, so Off set `directed` — which lit the Directed button, opened its controls and made a second Off press a no-op. Off clears everything now, and the comment that claimed otherwise is gone. The real fix is that marks do not belong inside a record whose mode describes a style they have nothing to do with.
- **The unreachable draw fallback is gone, and its test now takes the path it names.** `randomGlitch`'s first iteration always pushes, so the zero-token fallback could not run, and the test named for it passed a source where the loop succeeded first time — it would have stayed green with both deleted. What the attempt bound does is stop a pinned source from spinning, and the test now pins one that collides every time.
- **The surface clause matches the counts it was given.** Surfaces are chosen independently of marks and nothing caps them against each other, so three marks with two surfaces produced "a different one for each mark" — an instruction that cannot be followed.

- **The prompt now describes the contract it is compiling for.** The shared core stated the base contract's style placement for every mode, including Ref2VA, whose serializer writes the style as its own sentence before `[Shot 1]` — so a model obeying the core returned a clause and a lowercase opening, which cannot reproduce the guide's own worked example for that mode. Placement moved into the mode blocks, where it belongs.
- **The continuity fields the schema requires are named in the prompt.** `crossesCut` and `cutoff` are required on every dialogue beat and appeared in no prompt, so a model marking a line that spans a cut produced `SCENETRANS_UNPAIRED` for a tag it was never told to write — unclearable, since the patch validator will not rewrite prose. The speech block now teaches both, with the four continuity phrasings of base 4.4, which also gives `CONTINUITY_PHRASES` its first caller.
- **The punctuation instruction is scoped to lines the planner writes.** It said supplied dialogue is preserved exactly and then told the model to end every line with a terminal mark. Following the second rewrites the user's words, which makes `assemble` stop matching them against `suppliedDialogue` — so the document records them as not user-supplied and the punctuation rules deliberately scoped away from them start applying.

- **A retention line names which reference label it is about, and a slot can carry a second sentence.** Ref 2.5 lets one slot yield both `<Video N>` and `<Audio N>`, and ref 4 asks for one line per label — between the two the compiler had four silent defects, all reproducible on the guide's own examples. The serializer chose the label by inspecting the retention marker, and `weak_reference` is in both marker vocabularies, so ref 4.1's own `<Video 1> (cut and pacing structure): weak_reference` line rendered under `<Audio 1>` and the Video label got no line at all. Coverage keyed by slot, so one entry cleared both labels and nothing reported the loss. The marker-class rule treated any slot carrying a Video label as visual-only, making `fully_copy` on the audio line — the correct ref 4.2 marker and ref 2.5's own example — an error with no way to satisfy it. And `subject_definitions` read one description per slot, so the same sentence rendered twice, once describing a video under an Audio label. `RetentionTarget.labelKind` and `ReferenceSlot.audioDescription` are both optional, so documents written before them keep loading and mean the primary label, which is what all of them have. The planner already returns the two kinds in separate fields, so `assemble` knows the kind and nothing downstream infers it.

- **The contract covers what the code exports, in both directions.** Every check bound what the spec declared against the code; nothing looked the other way, so an omission was invisible rather than a disagreement. `SLOT_ROLES` and four role partitions were absent entirely — 19 values deciding which label kind every reference asset gets and whether it earns a definition line — along with the continuity phrasings, both dialogue punctuation sets and the house `<d/>` token. Each vocabulary leaf now names the constant it describes, and a constant that lives elsewhere in the spec is listed by name rather than left to a substring match.
- **Every prompt block says where it came from, with the same key the vocabulary uses.** The blocks are where house rules are actually written into the model's instructions and they were the least attributed part of the spec: one marked `origin: "house"`, five with nothing, and the patch prompt with nothing on any block. `MODE_SLOT_MISMATCH` was cited to base 1, which describes what each mode is and states no cardinalities at all — the counts it enforces are house policy. The `$schema` pointer named a file that has never existed.
- **`CAMERA_PROSE_HINTS` is gone.** A table of verb forms per camera motion whose comment claimed the validator used it to confirm the prose expressed the annotated motion. No such rule was ever written, and writing one is the prose pattern-matching this project purged seventeen rules of — "the camera holds" and "the frame stays put" are both a static shot. `DIALOGUE_TERMINALS` and `DIALOGUE_ALLOWED_PUNCTUATION` were dead beside it while the rule that needed them hardcoded its own; they are wired up now, which also removes the disagreement between the constant and the message it produced.

- **Four validator rules had a green half that was handed nothing to look at.** Every control asserts its code is absent from known-good input, which is the cry-wolf check — and the five golden fixtures contain no voiceover, no on-screen text, no line crossing a cut and no truncated speech, so `VOICEOVER_PHRASE_MISSING`, `VISIBLE_TEXT_NOT_QUOTED`, `SCENETRANS_UNPAIRED` and `CUTOFF_NOT_AT_END` were asserting silence about features nothing exercised. `test/fixtures/exercised.ts` fills the gap with four documents that validate clean and are deliberately not golden, since the goldens must stay byte-exact reproductions.
- **`Control.inspects` is required, so a rule cannot ship with a hollow green.** One predicate per code naming the input class its rule examines, checked against the fixture the green half runs on — the same shape as the control-coverage meta-test that refuses a code with no red. Its honest limit is stated where it lives: it proves the corpus holds an input the rule inspects, not one that would expose the rule's bug. It would not have caught the `userSupplied` scoping error, because the corpus does carry a supplied line and the rule was rightly silent about it.

### Removed

- **The fifteen presets, and the mode they lived in.** Each asserted that a particular pairing of four pack ids was worth having, and none had ever been checked against real H3 output — a name on an unverified guess borrows authority it has not earned. Directed mode picks the same four things and wild draws them behind an actual leverage test. `'exploratory'` stays in the stored union because documents written under it exist; it restores as `directed`, which is what it always was underneath, and a control proves both halves of that.

### Changed

- **`test/guide-fidelity.test.ts` says what it does not establish.** Both of its checks look only at the five worked examples, so a copy of the base guide with its field descriptions rewritten around intact examples passes every assertion in the file — one was tried, and all four base-guide fixtures matched it byte for byte. What separates such a copy from the official text is the sha256 pin in `contract.sources`. The header now says so, so the pin is not relaxed later on the grounds that fidelity covers it.
- **The glitch mode notes assert the property instead of five sentences.** Each mode's note was pinned by a specific sentence, which measured the wording rather than the thing that matters: that every mode is told something different and told only its own. The notes are read out of the table now, so a reword is invisible to the test and a copy-pasted note is fatal to it. Proven all three ways — red when two modes share a note, red when the lookup is hardcoded to one mode, and green when a note is reworded to say the same thing, which is the case the old test got wrong.
- **A test that breaks whenever the logic changes is a change detector, not a test.** The other half of the red/green rule, and the more common failure: proving a check can go red establishes only that it is coupled to the line you edited. What makes a red informative is that the test would not have fired for a legitimate change to the same code. Evidence from this session — an assertion pinned the exact sentence `do not add a full stop it does not have`, and it failed when a parallel clone reworded that instruction to say the same thing better. The prompt assertions with a real anchor now use it: the rendered shape `[Shot 1] <style>, <your first beat>`, field names, tag literals, and pack directives read out of the table rather than copied from it. The ones with no anchor say in the test that they are wording proxies.
- **The red/green rule says where a breakage earns itself.** It read "a check is unverified until it has been shown to go red for the right reason", which is true and, taken as a ritual, produces theatre: changing a constant to watch its own equality assertion fail proves nothing and trains you to read "went red" as "is sound". The question a breakage answers is whether the check reaches its subject, so it belongs where a green could come from never arriving — across a schema, a barrel, an assembly step, a UI path, or beside a second guard that could be carrying the assertion alone. That is not licence to skip it: deleting the creative-mode stamping from `compile` left the whole suite green because it sat past the model call, and `{setting}` versus `{setting:random}` had no control at all under a describe block whose name said the case was covered.
- **A red is information about the check, not a pass mark.** From an axis check written in another clone: its first version went red against nine packs that correctly claim no axis, and the failure was the check encoding a property that sounded right rather than the one the table has. Recorded in `CLAUDE.md`, with the same point carried into `VISION.md` and the header of `test/validate.test.ts` — which is the case where a breakage plainly does earn itself, since a diagnostic nothing can make fire is decoration.

- **A creative selection travels; its directive text does not.** `CompileInput.style`, which carried a resolved envelope of prompt text plus the inputs that produced it through eight files, is now `CompileInput.creativeMode` carrying only the mode and the pack ids. The planner and patch prompts each derive the directive themselves, from the same record through the same function. Before, one path was handed pre-resolved text and the other built a different shape by hand, which is how the two would have drifted apart.
- **The pack tables are the single source for their family.** Ids, names, directives and strength axes now come out of one array per family, with the id union derived from the data the way `vocab.ts` does it. Adding a pack was a three-place edit across two files; it is now one place, and a pack cannot exist without a score.
- **Reference anchors have string ids (`R01`-`R30`) and share one id space with the packs.** The `string | number` union behind them was the sole cause of three separate branches — a `typeof` fork in the scorer, a `z.union` in the schema, and two-branch handling in the resolver. A stored document naming an anchor by its old number resolves to no style rather than failing to open.
- **The creative picker holds no state of its own.** The selection lives in `useEngine` and the panel is driven by it. Checked in a browser against a seeded document: the four dropdowns come back with the stored selection, and changing one preserves the other three.
- **The module exports only what something calls.** `wildPresets` and `getPreset` were defined, exported and — in the first case — tested, with no caller anywhere; `getAnchor` and `getVisualPack` were superseded by the single `getVisual` lookup the moment packs and anchors shared an id space; `activeAxes` is used only by the rule beside it and is no longer exported. Four are gone; the fifth stopped being public. This is the same shape as the dead schema fixed below, found by looking for it after.
- **The picker says when it describes the next generation rather than the open document.** The two carry different facts — what the next generate will use, and what the current prose was written under, which is what an assisted edit preserves. Changing the picker without regenerating left the badge and the patch prompt saying different things with nothing to indicate it.
- **A restored selection drops pack ids this build no longer has.** `pruneSelection` runs where a stored record enters the UI. The derivations already skipped an unresolvable id, but left in the selection it rendered as a blank dropdown and rode along through every later edit without ever being visible.
- **Strength is a scope, not a volume knob.** Each level states its own authority over the request, and the core planner instruction defers to the section rather than claiming a blanket override — `subtle` previously said to keep the treatment grounded while the core prompt said the direction overrode the request, in the same prompt.


- **`device` key mode is decrypt-only.** It derived the AES key from `navigator.userAgent + navigator.language`, which is public. Existing envelopes still open, so nobody loses a stored key, and the next save upgrades them to `origin`. A stored key that cannot be decrypted at all is now cleared rather than left in place claiming a key exists that will never open.
- **`DB_VERSION` removed.** Nothing read it once the schema, rather than the version number, became the test for what exists. Keeping an exported constant that no longer governs anything invites someone to open at it.
- **`fake-indexeddb` is a devDependency again.** It was dropped in 0.3.0 as unused; the storage tests need a real IndexedDB implementation rather than a mock. Dev-only, so the five packages reaching the bundle are unchanged.
- **README and CLAUDE.md both state what this is**: one person tinkering, no roadmap, no support, no reviewers, possibly no users.
- **Security section rewritten.** It is now a short statement of what is stored, where, and what leaves the machine, and says plainly that this is a personal-tool posture and wrong for anything shared. Detail moved to a new **Under the hood** section at the end, which states the sample size of its own checks: one browser, one machine, by hand.
- **Claims cut back to what the evidence supports.** "Interactions are never stored server-side" conflated `store: false` with Google-side retention generally; the flag opts out of Interactions conversation-state storage and nothing more, while abuse-monitoring logging and free-tier product-improvement terms apply regardless. Dependencies are now described as trusted rather than audited.
- **Layout section said the database has five stores.** It has three: `documents`, `versions`, `settings`.

### Fixed

- **A restored directed selection was invisible and the first change destroyed it.** The picker held the four pack choices in its own state, initialised empty. After a reload the badge showed the stored style but every dropdown was blank, and changing any one of them read the empty local copy, found no visual medium, and silently cleared the style. Presets and wild rehydrated correctly, which is what made it easy to miss. The panel is now driven entirely by the record passed in, so there is one copy rather than two.
- **A document written with a reference anchor selected would not parse.** Anchors moving to string ids narrowed the stored `visual` field to a string, and every document carrying the old numeric form then failed the new schema check, showed a notice on every load, and had its style silently dropped. `getVisual` now understands both forms and `pruneSelection` rewrites the old one, so such a document opens clean and comes back with its anchor. This is precisely the tightening the rule added in the same change forbids; it was caught by review, and the control that would have caught it is now in `test/creative-integration.test.ts`.
- **A schema notice could bury the notice saying the stored API key was gone.** Both are set in the same effect and the second overwrote the first, so a browser that failed to decrypt the key and failed to parse the document reported only the document. They are concatenated now.
- **`H3DocumentSchema` was dead code.** It was defined, exported, maintained, and imported nowhere, so nothing validated a stored document and the round-trip safety it was described as providing did not exist. It is now checked at the load boundary and reports rather than gates: a document that fails to parse is still opened, with the offending path surfaced as a notice, because a build that refuses to open what the previous build wrote loses work that exists nowhere else. Confirmed in a browser as well as in tests — a hand-damaged document opens, keeps its shots and its creative mode, and names its own defect.


- **The same wedge in the document database.** `H3TransformationEngine` opened at a hardcoded version 1 with unconditional `createObjectStore`, so a database that already existed at version 1 without its stores never got them and every call threw `NotFoundError`. It now opens without naming a version and treats the stores *and their indexes* as the test — a `versions` store missing its `documentId` index breaks the history view exactly as silently as a missing store. Repair creates only what is absent, so existing rows survive; `test/db.test.ts` asserts that rather than assuming it. Three controls confirmed the tests go red: restoring the fixed-version open, dropping the index check, and removing the create guards. Also checked in Chrome against a hand-wedged database carrying real rows — repaired to version 2 with nothing lost.
- **A key vault stuck at version 1 with no object store could never be repaired.** `openDB(name, 1, ...)` skips `upgrade` when the database is already at version 1, so every later call threw `NotFoundError` and the app could not store a key again, silently. Anything else on the origin calling `indexedDB.open('H3KeyVault')` creates exactly that database; it happened by accident during testing. The vault is now opened without naming a version, with the presence of the object store — not the version number — as the test, bumping only when it is missing. The first attempted fix hardcoded version 1 on reopen and failed the other way with `VersionError`; the regression test caught it.
- **Saving an API key without a passphrase threw and the failure was invisible.** `useEngine` still asked for the retired `device` mode, which `setSecret` had started rejecting, and `saveApiKey` did not catch it, so the form looked like it had saved. The whole unit suite passed while this was broken. `WritableKeyMode` now excludes `device` so `tsc` rejects it at build time, the runtime throw stays as a backstop for untyped callers, and a storage failure is reported in the UI.

- **`connect-src` no longer lists bare `ws:`/`wss:`.** Those are scheme-wide sources matching any host, so they left a compromised dependency a socket to anywhere — the exfiltration route the rest of the policy exists to close. They were there for the Vite hot-reload socket, which `'self'` already covers. Probed both ways against the real policy: before, a `fetch` to an unrelated origin was refused while a `WebSocket` to that same origin went through; after, both are refused, the Gemini endpoint stays reachable, and dev HMR still connects.
- **`frame-ancestors` removed from the `<meta>` CSP.** The directive is ignored there, so it was never doing anything. Noted in the README as needing a response header.

Deliberately narrow — the guide's own summary describes actions, shot count and the ending, and stays green.

- Schema `describe()` strings no longer few-shot the model toward live action.

## [0.1.0]

First working version: the compiler is complete for all five modes and there is an editor on top of it.

### Added

- **Document model** (`src/core/ir`). Types, zod schemas, path addressing, and the closed vocabularies from both official guides. Slots and subjects are separate registries with a many-to-many between them, because one subject may draw on several assets and one asset may supply several subjects.
- **Normalizer** (`src/core/normalize`). Duration arithmetic including the 17k+5 frame grid, reference label assignment, mode inference from slot roles, and shot/word budgets. Everything computable without a model is computed here and supplied to the planner as fact.
- **Validator** (`src/core/validate`). 51 rules across contract structure, duration, shot numbering and cut times, alignment strings, camera vocabulary, the speaker registry, dialogue and voiceover, cross-cut tags, visible text, the audio sections, Ref2VA labels and retention, and slot ceilings.
- **Source-mapped serializer** (`src/core/serialize`). Both output contracts, with a character range recorded per document path so the rendered prompt links back to the nodes that produced it.
- **Patch pipeline** (`src/core/patch`). Path-scoped edits behind three gates: an allowlist that keeps derived values derived, an existence check that refuses auto-creation, and a guard that makes user-supplied dialogue immutable.
- **Gemini Interactions client** (`src/provider`). One narrow call shape with the API's verified behaviour encoded: `store: false` always, `temperature` never sent, `thinking_level` and `system_instruction` on every call, and a five-way status branch that treats truncation as terminal and distinct from failure.
- **Planner and patch prompts** (`src/provider/prompts`). Shared core plus per-mode blocks, carrying only rules that need semantic judgment.
- **Storage** (`src/db`, `src/crypto`). Five IndexedDB stores and an immutable version tree with branching. API key storage offers a device-derived mode and a passphrase mode, named for what each actually provides.
- **Editor** (`src/ui`). Slot manager with role assignment and derived-label readout, document tree editor, rendered prompt with click-to-select and inline diagnostics, and branch history.

### Verified

- Five golden fixtures reproduce the worked examples from both official guides byte for byte, and all five validate with zero errors.
- Every diagnostic code has a control fixture that makes it fire; a meta-test fails the build if any emitted code lacks one, and that meta-test was itself proven able to go red.
- A purity test keeps `src/core` free of React, the SDK, the database layer, the DOM, and `fetch`.
- 161 tests, clean typecheck, clean production build.

### Notes

- Two API unknowns were settled from the installed SDK types rather than by guessing: `generation_config.thinking_level` is snake_case with values `minimal | low | medium | high`, and `response_format` is `{ type, mime_type, schema }`. Two remain for the live probe script: the model id form and browser CORS.
- Video and audio references are not sent for analysis. Those need a Files API upload with PROCESSING polling and 48h handles; the slots take a written description instead.
